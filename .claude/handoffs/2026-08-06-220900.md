## PHILOSOPHY & DECISIONS

| Decision | Rationale | Rejected |
|----------|-----------|----------|
| Truth table beats the plan's own sketch | It won **4 times** this session (see below) | "Reconciling" toward the plan sketch |
| `NOT_APPLICABLE` ≠ `UNKNOWN` ≠ `GLOBAL` | Collapsing them is the `scenarioKey=null` bug the whole project exists to kill | One nullable field |
| `UNKNOWN` has exactly one representation `{state:'UNKNOWN'}` | Two ways to say it guarantees they diverge | `'UNKNOWN'` inside value unions |
| Hard filtering must not kill recall | Only definite CONFLICT excludes; UNKNOWN is held and visible | Excluding on UNKNOWN |
| `ModelRelationship` stores the FACT | Two models from one vendor share failure modes; "FULL independence" was an overclaim | `graderIsIndependent: boolean` |
| Eager stream operation | `created ⟹ completion settles`, no consumer-side precondition | Lazy generator behind an eager-looking promise |
| Provider `finish_reason` over heuristics (#70) | The API states truncation as fact; a response cut at an element boundary is still valid JSON and no heuristic can see it | Bracket-balance guessing alone |
| A green bot check is NOT a review | CodeRabbit reported `pass` on ~all PRs while rate-limited/skipped | Trusting the check mark |

### Four times the truth table beat the plan sketch
1. `PROCEDURE_STEP` has **no** `service` facet (only `PRICE_RULE` does).
2. `requiredFacets` are **unconditional**, not audience-dependent.
3. `QueryFrame` facets must be **required keys** with explicit `UNKNOWN` — a query has no `kind`, so an
   omitted key would be a second way to say UNKNOWN.
4. The plan's §-numbering for the truth table is **wrong**: it cites "§3.1 SCOPE matrix / §3.2 mandatory
   fields / §3.3 trigger / §3.4 multi-unit", but §3.1–§3.4 are the four *dimensions*; mandatory fields
   are §2/§2.1, activation §4.1 п.2, conflicts §4.1/§4.2. Consequence: **`audience` belongs to
   eligibility, not scope.**

## HOW TO WORK — the process that actually caught the bugs

**Verify every agent claim before merging.** Three separate agents this session reported fixes that
were **not in the code**; an independent reviewer caught every one. Concretely:
- A3 said it had added `trim()` for whitespace-only assertion strings — it had, but on a *different
  field*. `" "` in `expectedSubstrings` still matched nearly every answer.

**Run the suite yourself. Mutation-test the core guarantee** — break it deliberately, confirm a
specific test fails. **And confirm the mutation actually applied**: this bit me twice (a `perl` regex
silently didn't match, and a test passed with a guard disabled because the repaired input threw the
same error type for a different reason). A no-op edit and a passing test look identical.

**Always run Codex on the diff before merging.** On B2 it found three real bugs that Grok, the agent's
own adversarial pass, **and** my mutation testing all missed — including `isDecisive` ignoring
`supersedes`, which let a decisive unknown produce a confident answer. Codex also reviewed merged
code retrospectively and found three flaws in a detector I wrote myself (that became #70).

```bash
git diff master... | ~/.grok/bin/grok.exe --effort high -p "..."   # Grok
codex exec --skip-git-repo-check "Review ... Answer ONLY these, citing line content: ..."
```
Ask Codex **narrow, falsifiable questions** ("can X reach Y?"), and tell it to say so plainly if it
finds nothing. Note `codex exec` sometimes produces no output — retry rather than assuming clean.
`grok.exe` runs agentically in the cwd and has twice written scratch test files into a worktree —
`git status` after invoking it.

### Recurring defect class — check this first in any new schema
**"Well-formed but semantically empty."** Six instances in one day: whitespace-only assertion
substrings, reviewer identity, evidence quote, ambiguities, `messageId`, and a scenario *value* that
was never checked against its registry while the *key* was. `nonBlankString`
(`src/lib/knowledge/applicability/text.ts`) is the single implementation — use it.

### Windows worktree hazard (`translation-yg9`) — READ BEFORE CLEANUP
Worktrees get `node_modules` as a **junction** to the real store. `Remove-Item -Recurse -Force` on a
worktree **follows the junction and destroys the shared store** — this happened, emptied
`node_modules/.bin`, and broke `tsc` everywhere until `pnpm install`. Correct order:

```powershell
cmd /c rmdir "C:\dev\translation\.claude\worktrees\<name>\node_modules"   # unlink FIRST
```
```bash
git worktree remove --force .claude/worktrees/<name>
```
Create with:
```powershell
New-Item -ItemType Junction -Path "...\<worktree>\node_modules" -Target "C:\dev\translation\node_modules"
```
