## ЧТО СДЕЛАНО ЗА СЕССИЮ

### 1. Цены берутся из тарифной сетки (PR #40, #42)

Сетку движок раньше не читал вовсе. Теперь три пути:

- **контекст синтеза** — строки прайса кладутся в промпт первым блоком с приоритетом над
  правилами (`src/lib/knowledge/tariff-context.ts`). Отбор идёт **разделом**, не строкой:
  синонимы у услуг были пусты, и «ТПП СПб (от 2-х дней)» не находилась вопросом «заверение
  в Торгово-промышленной палате»;
- **сторож устаревших цен** (`stale-price-check.ts`) — на выходе, взводит ручную проверку;
- **детерминированная ветка** — отвечает ценой, только когда база не нашла ничего.

Синонимы засеяны: 23 услуги, 63 синонима, `scripts/seed-tariff-synonyms.ts --apply` идемпотентен.

### 2. Песочница перестала врать и спамить (PR #45)

- `deriveDecision` (вторая копия политики отправки с порогами 0.5/0.7 в браузере) удалена.
  Расхождение измерено: при уверенности 83% браузер показывал «черновик готов», сервер решал
  `escalate`;
- **песочница слала настоящие уведомления** — каждый прогон оператора создавал черновик
  пробела знаний и слал сообщение супер-админам. Флаг `sandbox` глушит побочные действия,
  признаётся ТОЛЬКО по сессии сотрудника;
- оба контура (сотрудник/клиент) показываются рядом одним запуском.

### 3. Видно, ПОЧЕМУ ответ такой

`debug.reasons` при `includeDebug`: какие из восьми контролей сработали и с какой находкой,
сколько строк прайса ушло в промпт, какие числа не заземлились. Плюс `deliveryBlocker` —
что именно помешало отправить.

### 4. Петля обратной связи от оператора

Модель `HeldAnswer`. Кнопка вердикта **под сообщением об эскалации** в Телеграме:
«Черновик был верен / неверен / неполон». Отчёт `report-held-answers.ts` считает по каждому
контролю, сколько он удержал ЗРЯ.

### 5. Замеры

| скрипт | что мерит |
|---|---|
| `measure-sent-error-rate.ts` | долю ошибок среди ОТПРАВЛЕННЫХ — цель владельца |
| `measure-guard-quality.ts` | контроль ловит подложенный дефект / молчит на верном |
| `probe-live-contours.ts` | оба контура по корпусу, JSONL + HTML |
| `report-held-answers.ts` | цена контроля в отнятых верных ответах |

## ИЗМЕРЕННЫЕ ЧИСЛА (не выдумывай новые, пользуйся этими)

**Доля ошибок среди отправленных** — первый замер, клиентский контур, 39 вопросов:
отправлено 16 (41%), ошибок 1 = **6,3%**, ДИ **1,1–28,3%**. Цель 2% **НЕ ДОКАЗАНА**:
интервал её накрывает. Неполных 8 из 16.

**Что держит ответы.** Прогон 30 самых частых вопросов: из 15 удержаний клиенту
**11 — низкая уверенность движка**, 4 — контроли. Из восьми контролей сработали три раза
три. Вывод: держит не восьмёрка контролей, а самооценка движка. Оговорка: 30 частотных
уникальных вопросов — не случайная выборка трафика, один прогон не мерит устойчивость.

**Качество контролей** (125 реальных ответов с подмешанными дефектами):

| контроль | молчит на верных | находит подложенное |
|---|---|---|

| утечка контура | 123/125 (98%) | **125/125 (100%)** |

Находимость ценовых занижена: подмена суммы там, где услуга прайса не названа, для них вне

## АРХИТЕКТУРА: КАК ПРИНИМАЕТСЯ РЕШЕНИЕ

```
вопрос
 → сценарный гейт (scenario_clear | needs_clarification | out_of_scope)
 → canonical Q&A override (совпадение ≥0.55 значимых слов, обходит гейт)
 → территориальный сторож (Москва↔СПб, детерминированный)
 → уточнение с кнопками  ИЛИ  открытый поиск  ИЛИ  честный отказ
 → гибридный поиск (вектор + ключевые, правила/пары/чанки, бусты авторитета)
 → ПРАЙС В КОНТЕКСТ, если вопрос про деньги
 → синтез моделью
 → consistency gate + одна регенерация
 → ВОСЕМЬ КОНТРОЛЕЙ → requiresHumanReview
 → (если база пуста) детерминированная ветка прайса → общие знания
 → ПОЛИТИКА ДОСТАВКИ: clarify | answer | escalate
 → (при escalate) запись HeldAnswer + кнопки вердикта оператору
```

**Пять условий отправки**, первое несработавшее и есть причина
(`explainAutoAnswer` в `auto-answer-policy.ts`):
`auto_answer_disabled` → `human_review_required` → `general_ai_source` →
`confidence_level_too_low` → `below_min_confidence`.

**Восемь контролей** — реестр `HUMAN_REVIEW_CHECKS` в движке, тип
`Record<HumanReviewReason, () => ReasonDetail | null>`:
`consistency_failed`, `unsupported_claims`, `knowledge_gap_phrase`,
`composite_capability_risk`, `client_safety`, `ungrounded_numbers` (только клиент),
`price_attribution`, `stale_price`.

Живые настройки прода: **автоответ включён**, порог **0.5**, модель `gpt-4o`.
Уведомления получает только Филипп (Яна, Зина, Daria — выключены,
`scripts/set-telegram-notifications.ts <id> on|off`).

- **Не запускать подагента в общем рабочем дереве** — он переключит ветку под тобой.
  Только `isolation: "worktree"`.
- **Не деплоить из дерева, где работает агент** — выкатишь его незавершённое.
- **Не гонять клиентский контур прогона по проду без `sandbox`** — владелец получит
  уведомление на каждый вопрос.
- **Не расширять ворота на слово о цене ради полупроцента** — проверено, +1 вопрос.
- **Не чинить приписку цен правилом «не та единица — значит не та услуга»** — убивает шесть
  настоящих находок.
