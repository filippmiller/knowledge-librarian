## ARCHITECTURE & FLOW

Как схема попадает на прод — это ключевое место, где всё ломалось:

```
git push master
   └─> Railway (авто-деплой НЕНАДЁЖЕН — всегда `railway up --detach` вручную)
         └─> Docker build (railway.toml → Dockerfile) → pnpm build
               └─> контейнер стартует
                     └─> Next.js instrumentation: src/instrumentation.ts → register()
                           └─> AWAIT bootstrapKnowledgeSchemaAtStartup()   ← здесь висло
                                 └─> pg_try_advisory_lock  → 13 идемпотентных DDL
                                       └─> статус в getLastBootstrapStatus()
                                             └─> виден снаружи: GET /api/health/schema
         └─> Healthcheck GET / , окно 5 минут → провал = деплой отменён, старая сборка остаётся
```

**Почему `prisma migrate deploy` не используется:** прод-БД исторически ведётся через `db push` и не имеет записи baseline-миграции — `migrate deploy` попытался бы накатить baseline поверх живых таблиц и упал. Отсюда самоприменяющийся идемпотентный DDL. Это осознанное решение, не чини его.
