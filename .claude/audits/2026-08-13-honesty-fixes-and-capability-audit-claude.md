## Вердикты по четырём главным вопросам владельца

### 1. «Мы на пике возможностей отвечать на бизнес-вопросы безошибочно?» — НЕТ

Гейты сборки в порядке: **2004/2004 тестов, typecheck чист, lint 0 ошибок, CI зелёный** на HEAD PR #76. Но в продовом пути ответа найдены и **воспроизведены исполнением** дефекты:

**1.1. Фильтр учреждений инвертируется на реалистичном тексте (КРИТИЧНО).**
`src/lib/knowledge/institution-scope.ts` + `filterCrossInstitutionEvidence`. Живой прогон (вопрос «Как поставить апостиль в КЗАГС СПб?», scenario `apostille.zags.spb`):

- ОСТАВЛЕНЫ: чанк ЛО без названия учреждения (вт/чт + пропуск 539-43-63) и чанк «Отдел ЗАГС Всеволожского района» — районные отделы ЛО детектором не распознаются вовсе;
- ВЫРЕЗАНЫ: чанк «Комитет по делам ЗАГС СПб (бывшее Управление ЗАГС города) — Фурштатская 52, 2500» (фраза «Управление ЗАГС» ложно даёт `zags_lo` → смешанный → дроп) и маршрутизирующий чанк «диплом — Минюст, СОР — КЗАГС» (правило «любой лишний скоуп = конфликт»).

Фильтр удержал ровно то, от чего должен защищать, и выкинул ровно то, что нужно для ответа. Ложные срабатывания детекторов: «Ленинградский проспект в Москве» → `zags_lo`; «оптиковолоконный» → `minjust`.

**1.2. Канонический QA-override обходит все фильтры.** `enhanced-answering-engine.ts:745-831`: выборка только по `authorityTag`/`origin` + term overlap, без сценария и без фильтра учреждений; результат — `confidence: 1.0`, `high`, `requiresHumanReview: false`, мимо retrieval, consistency-gate и delivery-gate. Одобренная операторская пара про ЛО может ответить на вопрос про СПб.

**1.3. Тарифный блок не фильтруется.** `:1352` → `tariff-context.ts:150` берёт ВСЕ строки секции; в `APOSTILLE_SPB` реально лежат и «ЗАГС СПб (2 недели)», и «ЗАГС ЛО (1–1,5 недели)» — ЛО-сроки попадают в промпт СПб-вопроса.

**1.4. `insufficient` + непустые чанки = ответ без верификации и без источников.** `:1474` пропускает consistency-gate при `insufficient`; новый код дополнительно стирает citations — непроверенный ответ выглядит бессource-ным.

**1.5. `buildClarificationResult` (`:2675`) отдаёт `insufficient` без `answerSource`** — инвариант «insufficient ⇒ none» нарушен на этом пути (маскируется `?? 'none'` в eval-раннере).

**1.6. Прод ≠ HEAD.** По хендоффу прод на `b902779` — с детектором, где «неделя вперёд»/«вт-чт» помечены как ЛО. По сегодняшнему исходнику КЗАГС («ЗАПИСЬ ТРЕБУЕТСЯ, на неделю вперёд») это значит: **прод сейчас вырезает верный факт КЗАГС из ответов про КЗАГС.** Фикс `39a1936` (2 строки) не выложен. Из этой среды выложить нельзя (нет railway).

По самим заявленным правкам Grok:
- `answerSource: 'none'` — структурно, из confidenceLevel, без подстрок. ПОДТВЕРЖДЕНО (с исключением 1.5).
- Фильтр учреждений — НЕ РАБОТАЕТ на реалистичных текстах (1.1), тесты фикстурно-удобные: каждая фикстура называет учреждение явно.
- Lint — polarity ловит ровно класс R-64 (проверено исполнением), но: только точные стемы (мимо «требуются», «не нужна», «без записи», «обязательна»); `PLACEHOLDER` (`extraction-lint.ts:28`) использует `\b` — «пример текста»/«заполнить» НИКОГДА не срабатывают (в 11 строках от комментария, объясняющего почему `\b` не работает с кириллицей); адреса без префикса «ул./площадь» и числа <3 цифр невидимы (полная подмена адреса «Фурштатская 52» ↔ «Оптиков 35к1» проходит чисто). Lint по-прежнему advisory и выполняется ПОСЛЕ записи правил в базу.
- Eval: почтовый кейс — честная метка текущего поведения, но ретрив-провал по существующему документу («Инструкция отправкой почтой РФ», наценки 30/40/50%) превращён в вечный зелёный: **задача на починку не заведена** (проверено по beads). Кейс «Китай» ослаблен: `source` удалён — теперь пройдёт и `general_ai`, и `none`.
- Ещё два мёртвых `\b` с кириллицей вне этих коммитов: `audience.ts:137` («к нам» никогда не матчится), `stale-price-check.ts:62-63` («стр.»/«док.»).
- Ни один тест не вызывает `answerQuestionEnhanced` — стирание citations/primarySource на `none` не покрыто ничем.

### 2. «Нужно ли переизвлекать правила из документов?» — НЕТ (сейчас это было бы деструктивным холостым ходом)

- Новый типизированный контракт **не имеет модели в Prisma** (нет `KnowledgeUnit`, проверено по schema.prisma — 34 модели, ни одной под юниты) — переизвлечённые юниты некуда класть и никто в проде их не читает.
- Новый экстрактор пока не даёт решающих полей: замороженный приёмочный артефакт — **44 юнита, 0 юнитов с хотя бы одной KNOWN-фасетой** (перепроверено чтением `frozen-extraction/extraction-artifact.json`). Ворота применимости на таких данных — пропускной пункт без проверки.
- Переизвлечение деструктивно: `reprocess-all.ts` удаляет вместе с правилами `RuleComment`, `UserFavorite`, уведомления (строки 42-46; в схеме на Rule стоит `onDelete: Cascade`). Отката нет.
- Арбитр прав: карточки ЗАГС-документа фактически верны, дефект — дубли (~18 фактов → 55 карточек), и дедупа в кодовой базе нет (`rule-conflict-detector.ts` с `potential_duplicate` — мёртвый код без единого импортёра, проверено грепом).

**Дешёвая альтернатива с большим выигрышем (0 LLM-затрат):** прогнать все 1535 ACTIVE правил через `lintRule` + `locateQuote` (оба инструмента уже в репозитории) — механический отчёт «цитата не находится в источнике / полярность инвертирована / адрес не из цитаты», затем точечный retire (`status='DEPRECATED'`, паттерн уже есть). Это даст больше качества, чем любой пересъём.

### 3. «Система перевооружена: любой документ → parse → ingest → сразу отвечает?» — НЕТ

- **Форматы:** DOCX, PDF (только текстовый слой, без OCR), TXT/MD, RTF (наивно). **XLSX/CSV — нет. Email (.eml/.msg) — нет.** Неподдерживаемый тип → HTTP 400, документ не создаётся.
- **Веб-путь имеет 3 обязательных ручных шага:** открыть обработку → отметить staged-элементы (isVerified default false) → нажать commit. Это осознанный дизайн безопасности, но «сразу отвечает» — неправда.
- **`scenarioKey` для нового документа не назначается никем и никогда** (единственный писатель — `backfill-scenarios.ts` с хардкодом имён 3 апостильных документов). Правила/QA создаются с `scenarioKey=null`. Пока действует `IS NULL OR IN (ancestors)` — контент находится, но это ровно та дыра, из-за которой понадобился фильтр учреждений (1.1).
- **`audience` ставится только CLI-скриптом** — новый документ по умолчанию `INTERNAL_ONLY`, клиентские ответы его не видят.
- **pgvector:** `embeddingVector` при commit не пишется вообще; единственный писатель — ручной `migrate_embeddings`. Если pgvector активен в проде, новые чанки невидимы для семантического поиска до ручной миграции. (In-memory фолбэк работает сразу — какой путь активен в проде, отсюда не проверить.)
- **Кэш ответов** 30 минут, инвалидации при ingest нет — свежезалитое знание может полчаса перекрываться старым ответом.
- **Telegram-путь — единственный автоматический** (без staging), но молча обрезает документ: классификация видит 4000 симв., извлечение — 8000. 50-страничный документ = правила из первых ~8k символов без предупреждения; провал JSON-парсинга → 0 правил при статусе COMPLETED.
- Именной модуль ветки `docx-canonical-blocks.ts` в продовом ingest не участвует — прод парсит через `mammoth.extractRawText`.
